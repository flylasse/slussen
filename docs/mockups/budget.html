Buttons that answer back

Adopted from the predecessor: the pressed button carries its own state. Changed: the provider-wait state offers no retry that skips the wait (UC-001 BR-004), a Request Limit warning asks for confirmation instead of blocking (UC-001 BR-015), and reading the Budget App is its own action.

Fetch Cooldown (UC-001 A2)

A Fetch now is answered from the stored data of the last Fetch and recorded as Served From Fetch Cooldown. The Fetch Cooldown is 60 minutes by default, an Operator Setting; 0 switches it off.

✓ Served from the Fetch of 13:20 · contacts SimpleFIN again from 14:20

Waiting for the provider (UC-001 A1, A5)

The Data Provider or a Bank asked Slussen to wait: the period it named, or the default wait (8 hours by default, an Operator Setting). No action ends it, so no retry button is offered.

Waiting for the provider until 22:10

Request Limit warning (UC-001 A15, A16)

Scheduled Fetches pause; a Fetch you start first shows the warning and the risk, and needs your confirmation.

Request Limit warning · Fetch anyway…

Request Limit reached (UC-001 A3)

No request until the oldest counted one leaves the window. The Request Limit is set per Data Provider in the Build Configuration (24 by default), counted over the preceding 24 hours, the window of the Data Provider's own limit.

Request Limit reached · frees up from 21:14

Failed (UC-001 A6)

A timeout, an outage or an unreadable answer starts no Back-off; you can fetch again at any time.

Failed 14:05 · no answer Fetch again

Configuration error (UC-001 A7)

The Data Provider refused Slussen's service credentials.

Configuration error · correct the Build Configuration

Missing or expired Bank Consent (UC-001 A4)

The Bank is not contacted; the action grants or renews the Bank Consent.

Renew Bank Consent

Reading the Budget App (UC-003)

Reads the Budget App only and gives every Bank Transaction its Transaction Status again; no Bank is contacted.
