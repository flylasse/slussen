# Requirements: Slussen

Requirements catalog for Slussen, derived from `docs/vision.md`. Roles are the **Operator** and the **Adopting
Developer** as defined in `docs/glossary.md`. Domain terms follow the glossary.

## Functional Requirements

| ID     | Title                                   | User Story | Priority | Status |
|--------|-----------------------------------------|------------|----------|--------|
| FR-001 | Fetch on Demand | As an Operator, I want to start a Fetch of transactions and balances for the fetch period (the last 60 days by default, a number I can change) from one Source, from the Sources that have a Bank Account in one Budget, or from all Sources, myself at any time so that I get the latest transactions when I want them. | High | Open |
| FR-002 | No Automatic Fetch | As an Operator, I want Slussen never to fetch, compare against the Budget App or upload on its own, in the background or on a schedule so that every Bank access and every write is one I started. | High | Rejected |
| FR-003 | Open on Stored Data                     | As an Operator, I want Slussen to open showing the transactions, statuses and balances it last stored, without contacting any Source so that opening the app costs no Bank access. | Medium | Open |
| FR-004 | Booked Transactions Only                | As an Operator, I want only booked Bank Transactions to be taken in, and pending ones left out until they are booked so that a transaction is brought in once, in its final form. | High | Open |
| FR-005 | Skip Zero-Amount Transactions           | As an Operator, I want Bank Transactions with an amount of zero to be left out so that the Budget App receives no empty transactions. | Low | Open |
| FR-006 | Import a Transaction File               | As an Operator, I want to import a Transaction File I downloaded from my Bank, for a Bank Account that has no usable transaction feed, so that its transactions reach the Budget App without typing them. | High | Open |
| FR-007 | Reject a Faulty Transaction File        | As an Operator, I want a Transaction File that cannot be read completely to be rejected as a whole, with the reason shown, while the transactions from my previous import stay unchanged so that a faulty file never brings in part of its transactions. | High | Open |
| FR-008 | Balance for a File-Imported Bank Account | As an Operator, I want the balance of a Bank Account whose transactions come from a file to be fetched from a Data Provider where one reports it so that I can still compare that Bank Account's balance with the Budget App. | Medium | Open |
| FR-009 | Review Transactions Without Stable Reference or Unreadable | As an Operator, I want every Bank Transaction that has no Stable Reference, because its Source gives none or because two or more transactions of a file would get the same derived reference, and every transaction a Data Provider delivers that Slussen cannot interpret, kept as an Unreadable Transaction with whatever fields could be read and the reason, to be shown to me for review with the status Needs Review instead of being merged, guessed or lost so that no transaction is silently dropped or duplicated. | High | Open |
| FR-010 | Grant Bank Consent                      | As an Operator, I want to grant Slussen consent to read my Bank Accounts at a Bank by authenticating once per Bank with the Bank's own Strong Customer Authentication, started from my phone, so that Slussen can fetch from that Bank until the consent expires. | High | Open |
| FR-011 | Renew Bank Consent                      | As an Operator, I want to renew a Bank Consent the same way I granted it, from any place in Slussen that shows the consent is expiring or expired, so that I can restore access without searching for the action. | High | Open |
| FR-012 | Warn of Expiring Consent | As an Operator, I want every opening of the app to show each Bank Consent that expires within the consent warning lead time (7 days by default, a number I can change), with its expiry date and the action that renews it, without blocking any Fetch, so that I can renew it before access lapses. | High | Open |
| FR-013 | Hold Back Banks Without Consent         | As an Operator, I want Slussen to skip every Bank whose consent has expired or was never granted, without contacting it, while other Banks of the same Data Provider are still fetched, so that no Bank access is spent on a request that will be refused. | High | Open |
| FR-014 | Honour a Request to Wait | As an Operator, I want Slussen to wait as long as a Bank or Data Provider asks, or for the default wait when it names no period (8 hours by default, a number I can change), before contacting it again, for a Fetch I start and for a Scheduled Fetch alike, so that Slussen does not trigger further refusals or put my Bank Consent at risk. | High | Open |
| FR-015 | Retry After a Transient Failure | As an Operator, I want a timeout, an outage or an unreadable answer from a Data Provider to be shown with its time, to be able to start a Fetch again at any time, and a Scheduled Fetch that meets such a failure to wait for its next scheduled time, so that a passing failure causes no repeated calls I did not ask for. | Medium | Open |
| FR-016 | Fetch Cooldown After Success            | As an Operator, I want a Fetch of a Source that succeeded within its Fetch Cooldown (set per Data Provider: its default comes with the Data Provider's part, and I can change it or set it to 0 to switch it off), to be answered from what was already fetched without contacting the Source, and still to be compared with the Budget App, so that repeated presses do not spend Bank access. | High | Open |
| FR-017 | Request Limit per Data Provider | As an Operator, I want Slussen to send a Data Provider at most its Request Limit (declared by each Data Provider's part from the Data Provider's own limit, not changeable by me) in any rolling 24 hours (the window of the Data Provider's own limit), and, from the first warning the Data Provider gives about its limit, to make no Scheduled Fetch of it for the Request Limit warning pause (24 hours by default, a number I can change) while still letting me start a Fetch myself after showing the warning and the risk that further requests can get Slussen's access to the Data Provider disabled, so that Slussen stays within the Data Provider's own limit and the decision to go beyond a warning is mine. | Medium | Open |
| FR-018 | Isolate Source Failures                 | As an Operator, I want a failure in one Source or one Bank Account to leave the Fetch, Comparison and Upload of every other Source and Bank Account unaffected so that one broken Bank does not stop the rest. | High | Open |
| FR-019 | Compare With the Budget App             | As an Operator, I want each fetched Bank Transaction compared with what the Budget App already holds, including transactions deleted or merged there, and given a Transaction Status so that I can see per transaction whether it is new or already there. | High | Open |
| FR-020 | Send Matches for Typed Entries          | As an Operator, I want a Bank Transaction that matches an entry I typed in the Budget App (same Budget Account, same amount, within the Budget App's Matching Date Window) to be shown as a match and sent on Upload so that the Budget App pairs the two instead of holding both. | High | Open |
| FR-021 | Hold Possible Imports by Another Path   | As an Operator, I want a Bank Transaction that resembles an Import created by another import path in the same Budget Account (same amount, within the Budget App's Matching Date Window) to be held back from every Upload Plan until I decide, as a reason for review and not as a guarantee (keeping the Budget App consistent with Other Import Paths and my Typed Entries stays my responsibility), so that a likely duplicate is never written without my decision. | High | Open |
| FR-022 | Decide on a Possible Import by Another Path | As an Operator, I want to decide for each held transaction that it is already present (choosing the exact Budget App Transaction from a list showing date, payee, amount and Budget Account when there are several), that it is imported anyway, or that it is deferred so that every collision is resolved by me and never silently. | High | Open |
| FR-023 | Recheck an Already-Present Decision     | As an Operator, I want my decision that a transaction is already present to be checked again on every Comparison, and the transaction returned to me for review when the chosen Budget App Transaction was deleted, moved to another Budget Account or changed in amount, so that my decision never hides a transaction permanently. | High | Open |
| FR-024 | Keep Deferred Transactions Held         | As an Operator, I want a deferred transaction to stay held back across later Fetches, even when the resembling Import disappears, until I decide otherwise so that a deferral is never undone without me. | Medium | Open |
| FR-025 | Recognise Own Uploads                   | As an Operator, I want transactions Slussen itself sent to the Budget App never to be treated as Imports by another import path so that my own earlier Uploads do not hold back new transactions. | High | Open |
| FR-026 | Show Transactions Deleted in the Budget App | As an Operator, I want a Bank Transaction that Slussen sent and that I later deleted in the Budget App to be shown as deleted there and not sent again so that a deletion I made is respected. | High | Open |
| FR-027 | Show Transactions Merged in the Budget App | As an Operator, I want a Bank Transaction that the Budget App merged into an entry I typed to be shown as merged and not sent again so that a completed pairing is not mistaken for a loss. | Medium | Open |
| FR-028 | Re-upload a Deleted Transaction         | As an Operator, I want to choose, per transaction and off by default, to upload again a transaction that was deleted or merged in the Budget App or whose already-present decision no longer holds, as a new transaction while it is inside the Upload Window, so that I can recover a transaction I deleted by mistake. | Medium | Open |
| FR-029 | Change Decisions Until Upload           | As an Operator, I want to change or clear each Review Decision and Transfer Decision until the transaction is uploaded, after which it is locked, so that I can correct a mistake before anything is written. | High | Open |
| FR-030 | Upload Date Window                      | As an Operator, I want only transactions dated within the Upload Window, by default the last 7 days and adjustable by me, and not in the future, to be uploaded, and every transaction outside the window shown as too old or as in the future so that old or future-dated transactions never disappear silently. | High | Open |
| FR-031 | Age Out Visibly                         | As an Operator, I want a transaction that leaves the Upload Window while it waits for my review to stay visible with the reason it can no longer be uploaded so that a transaction I have not handled is never lost without notice. | High | Open |
| FR-032 | Block Bank Accounts With a Currency Mismatch | As an Operator, I want a Bank Account whose currency differs from its Budget's currency to be blocked from Upload and its balance Comparison hidden, with the reason shown, so that no amount is ever converted or written in the wrong currency. | High | Open |
| FR-033 | Prepare an Upload Plan | As an Operator, I want to prepare an Upload Plan for one Budget or one Bank Account that states the Budget, the Budget Accounts, the number of transactions to create and to match, the total inflow and total outflow, whether they arrive Cleared, every Transfer Counterpart that will be marked Cleared (none while Upload as Cleared is off), and when the plan expires so that I know exactly what will be written before I confirm. | High | Open |
| FR-034 | Upload Only on Confirmation             | As an Operator, I want Slussen to write to the Budget App only when I confirm an Upload Plan so that nothing is written without my explicit confirmation. | High | Open |
| FR-035 | Write Exactly What Was Confirmed        | As an Operator, I want Slussen to check the Budget App, the fetched transactions and the configuration again immediately before writing, and to write nothing and return me to review when any of them changed or the plan expired, so that what is written is exactly what I confirmed. | High | Open |
| FR-036 | Pause Other Work While a Plan Is Open | As an Operator, I want fetching (a Scheduled Fetch that falls due waits until the pause ends), file imports, Budget App reads, Bank Consent grants and revocations, Account Mapping changes and settings changes to be unavailable while an Upload Plan waits for my confirmation, with only confirm, cancel and Review Decisions allowed, and this pause to end when the plan is written, cancelled, discarded or expires, so that the plan cannot change under me. | High | Open |
| FR-037 | Truthful Upload Outcome                 | As an Operator, I want to be told per Budget Account which transactions were written, which were not, and which have an unknown outcome, and never to see an unconfirmed write as done, so that I know the true state of the Budget App. | High | Open |
| FR-038 | Resend Safely After an Unknown Outcome  | As an Operator, I want transactions whose Upload outcome is unknown to stay available for Upload under the same Import Identifier when the Budget App refuses a transaction whose Import Identifier it already holds, and otherwise to wait for my Review Decision after Slussen has checked the Budget App, so that a lost connection never causes a duplicate or a gap without my decision. | High | Open |
| FR-039 | Updated Statuses After Upload           | As an Operator, I want the statuses of all transactions in the uploaded Budget to be updated from the Budget App right after an Upload so that uploaded transactions are not offered for Upload again. | Medium | Open |
| FR-040 | Re-read the Budget App                  | As an Operator, I want to have Slussen read the Budget App again and update every Transaction Status without fetching from any Bank so that changes I made in the Budget App show up without spending Bank access. | Medium | Open |
| FR-041 | Exactly-Once Sent Record                | As an Operator, I want Slussen to record every transaction in its own durable Sent Record before sending it, never to send again a transaction the Budget App confirmed, and to send one with an unknown outcome again only as FR-038 allows, even after a retry, timeout, crash, reinstall or re-mapping of a Bank Account, so that Slussen never creates a duplicate on its own. | High | Open |
| FR-042 | Survive a Reinstall, Restore or Upgrade | As an Operator, I want my stored Bank Transactions with their history, the Budgets I chose, my Bank Accounts with their names and Start Dates and how Slussen recognises each of them, my Account Mappings, my review and Transfer Decisions, my settings and the Sent Record to be kept, as of the time the device backup was made, when Slussen is reinstalled and restored from a device backup, and in full when it is upgraded to a newer version of the same build, while Bank Consents with their Bank Sessions and the service credentials are not restored, so that I grant each Bank Consent and enter each credential again, so that none of these events creates a duplicate or exposes Bank access. | High | Open |
| FR-043 | Continue the Predecessor App's History | As an Operator, I want Slussen to continue the Predecessor App's history and Import Identifiers so that replacing the Predecessor App creates no duplicates. | High | Rejected |
| FR-044 | Imported Transactions Arrive Cleared | As an Operator, I want every transaction Slussen creates in the Budget App to arrive Cleared while Upload as Cleared is on (on by default, a setting I can change) and uncleared while it is off, and always waiting for my approval there, so that I approve each one in the Budget App and decide myself whether Slussen or I mark it Cleared. | Medium | Open |
| FR-045 | Switch Transfer Detection On or Off | As an Operator, I want to switch transfer detection on and off, off by default, so that without it every transaction is imported as an ordinary transaction. | Medium | Rejected |
| FR-046 | Detect Transfers Between Own Bank Accounts | As an Operator, I want Slussen always to detect two Bank Transactions of equal and opposite amount, in two of my Bank Accounts in the same Budget and currency, dated at most 5 days apart (5 by default, a number I can change), and recognised as a Card Payment (one side is a credit card) or as a Bank Transfer (the payee or memo of one side matches one of my Bank Transfer Descriptions), as one Transfer, and a single Bank Transaction whose payee or memo matches one of my Card Payment Descriptions or Bank Transfer Descriptions as a Transfer whose other side has not arrived yet, so that it can arrive as one linked transfer. | High | Open |
| FR-047 | Upload a Transfer as One Linked Transfer | As an Operator, I want a detected Transfer to be uploaded as one Transfer Leg that the Budget App links to the other Budget Account, never as two separate transactions, so that I do not have to re-link it in the Budget App. | High | Open |
| FR-048 | Never Pair Across Budgets or Currencies | As an Operator, I want movements between Budgets or between currencies never to be treated as Transfers so that each side stays an ordinary transaction and no currency is converted. | High | Open |
| FR-049 | Review Guessed Transfers                | As an Operator, I want a Transfer that Slussen cannot pair unambiguously to be flagged as guessed, with the number of Guessed Transfers shown per Budget, so that I confirm or correct each guess before Upload. | High | Open |
| FR-050 | Correct a Transfer | As an Operator, I want to confirm a Transfer, split it into ordinary transactions, hold it back, or choose the other Budget Account it belongs to, and optionally keep that Budget Account as the Funded By of a credit card Bank Account or as the Transfer Partner of any other Bank Account, so that every Transfer lands where I intend and later Transfers are proposed the same way. | High | Open |
| FR-051 | Transfer With One Side Missing | As an Operator, I want a Transfer of which only one side has arrived to be shown with the expected other side and proposed for the next Upload Plan as a linked transfer whose counterpart stays uncleared, and to become an ordinary transaction when its other side has not arrived within 6 days (6 by default, a number I can change), so that a Transfer is not held back indefinitely. | High | Open |
| FR-052 | Settle the Transfer Counterpart | As an Operator, I want the arriving Bank Transaction for the other side of a Transfer Slussen uploaded not to be uploaded again, and, while Upload as Cleared is on, the counterpart that the Budget App created to be marked Cleared then, so that the Transfer ends without a duplicate and, with the setting on, fully Cleared. | High | Open |
| FR-053 | Clear the Counterpart When Both Sides Are Present | As an Operator, I want a Transfer whose both sides were fetched to land with its counterpart marked Cleared at Upload while Upload as Cleared is on, and uncleared while it is off, so that the Transfer is complete on both Budget Accounts at once when I want Slussen to clear. | Medium | Open |
| FR-054 | Review a Changed Transfer Counterpart   | As an Operator, I want an arriving Bank Transaction whose Transfer Counterpart was changed or unlinked in the Budget App to be shown to me for review instead of being suppressed so that no side of a Transfer is silently lost. | High | Open |
| FR-055 | Only Clear Own Counterparts | As an Operator, I want marking a Transfer Counterpart as Cleared, and only while Upload as Cleared is on, to be the only change Slussen ever makes to an existing Budget App Transaction, and only for a counterpart created by a Transfer Slussen uploaded, so that the Budget App otherwise stays exactly as I keep it. | High | Open |
| FR-056 | Map Each Bank Account to One Budget Account | As an Operator, I want each Bank Account to be mapped to exactly one Budget and Budget Account, as I pair them in the app (FR-098), so that each Bank Account's transactions land in the right place. | High | Open |
| FR-057 | Lock a Mapping After First Upload       | As an Operator, I want the Account Mapping of a Bank Account to be locked once a transaction was sent through it, whatever the Budget App answered, with the reason shown wherever a change is refused, so that already-sent transactions are never created again in another Budget Account. | High | Rejected |
| FR-058 | Never Guess a Bank Account              | As an Operator, I want Slussen to use a Bank Account's transactions only when it identifies the Bank Account with certainty, to ask me to confirm when it can only propose a likely Bank Account, and to stop when two Bank Accounts are possible or two Account Mappings would point to the same Bank Account, so that one Bank Account's transactions are never sent to another Budget Account. | High | Open |
| FR-059 | Retire and Restore a Bank Account       | As an Operator, I want to retire a Bank Account so that it is no longer fetched, compared, matched or uploaded, and to restore it later with its identity and history intact, so that I can pause a Bank Account without losing anything. | Medium | Open |
| FR-060 | Separate Budgets                        | As an Operator, I want each Budget, with its own currency, to be shown as its own workspace with only its own Sources, Bank Accounts, transactions and number of transactions to upload so that I never mix up Budgets. | Medium | Open |
| FR-061 | Compare Balances                        | As an Operator, I want each Bank Account's balance shown next to its Budget Account's balance in the Budget App, with the difference and the time each balance was read, in one place so that I can reconcile them at a glance. | High | Open |
| FR-062 | Hide Outdated Balance Differences       | As an Operator, I want the balance difference of a Bank Account to be hidden and marked as outdated when its Account Balance is older than 36 hours (36 by default, a number I can change) so that I never reconcile against an old balance. | Medium | Open |
| FR-063 | Show Source Health and Freshness | As an Operator, I want each Source and Bank Account to show the outcome of its last Fetch or file import with its time, separately how old its data is, and the number of its transactions not yet uploaded, so that I can see at a glance whether the Budget App is up to date with each Source. | High | Open |
| FR-064 | Show the Blocked Reason and Its Remedy | As an Operator, I want every Bank Account or Source that cannot be fetched or uploaded to show the reason (for example missing consent, unrecognised Bank Account, waiting for the provider, Request Limit reached, access limit reached, credentials refused or missing) together with the action that removes it or the time it ends so that I know what to do. | High | Open |
| FR-065 | View Recent Fetch Outcomes | As an Operator, I want to see the most recent Fetch attempts (60 by default, a number I can change) with Source, time, whether I or the schedule started them, and outcome so that I can tell when each Source last brought data back. | Low | Open |
| FR-066 | Record the Decision Journal | As an Operator, I want Slussen to record what it fetched, the status it gave each transaction, every decision I made together with what Slussen had proposed, every Upload Plan and Upload, every Account Mapping change, and what later happened in the Budget App to each transaction Slussen sent, naming each transaction by its Bank Account and its Import Identifier, so that I can measure afterwards how often Slussen was right. | Medium | Open |
| FR-067 | Control the Decision Journal            | As an Operator, I want to switch the Decision Journal on and off (on by default), to set its size limit between 10 and 500 MB (50 MB by default), to be warned when it reaches the journal warning threshold (80% of the limit by default, a number I can change), and to clear it, so that it never fills my phone. | Low | Open |
| FR-068 | Export the Decision Journal | As an Operator, I want to export the Decision Journal to a file I choose, together with the Budget App's current transactions for my Budgets (or Slussen's stored copy of them when the Budget App cannot be reached, stated in the file), optionally with payee and memo text replaced by codes, naming each transaction by its Bank Account and its Import Identifier, holding the recorded facts only and no conclusions drawn from them, so that I can review Slussen's accuracy outside the app. | Medium | Open |
| FR-069 | Switch On Detailed Logging              | As an Operator, I want to switch on Detailed Logging that includes transaction data and Bank Account numbers, and switch it off again, so that I can troubleshoot a problem on my own phone. | Low | Open |
| FR-070 | Configuration Templates                 | As an Adopting Developer, I want a Configuration Template for the signing setup of an own release build that shows what to fill in and where to get it, and the app to state for each Data Provider and the Budget App in this build which credentials to enter and where to get them, so that I can set up Slussen without reading the code. | High | Open |
| FR-071 | Sign an Own Release Build | As an Adopting Developer, I want an optional Build Configuration that holds only the signing setup of my own release build, kept in a location the repository ignores, next to the Configuration Template, and never committed, while a debug build or an app someone else built needs none, so that I can build and install Slussen without putting anything personal into the repository. | High | Open |
| FR-072 | Add a Data Provider | As an Adopting Developer, I want to add a Data Provider as its own part, stating whether it gives each transaction a Stable Reference, so that I can bring in a Bank this build does not reach. | Medium | Open |
| FR-073 | Replace the Budget App                  | As an Adopting Developer, I want to connect Slussen to a different Budget App by replacing only the part that talks to the Budget App so that I can use Slussen with the Budget App my household uses. | Medium | Open |
| FR-074 | Own Import Identifier | As an Operator, I want every Bank Transaction to get an Import Identifier that Slussen derives the same way every time from its Source Key and Stable Reference (or, without one, from its own fields and its occurrence), that marks it as sent by Slussen, that is unique as NFR-020 requires, and that is sent with the transaction, so that Slussen and the Budget App recognise the transaction again, also after a reinstall. | High | Open |
| FR-075 | Start Date per Bank Account | As an Operator, I want each Bank Account to have an optional Start Date that I set and change in the app, and every transaction dated before it to be shown with that reason and never offered for Upload, so that Slussen takes over a Bank Account from another import path without sending what that path already sent. | High | Open |
| FR-076 | Scheduled Fetch | As an Operator, I want Slussen to fetch from all Sources on its own on a schedule, twice in any 24 hours by default, a number I can lower to once or to zero to switch it off, so that new transactions are waiting for me when I open the app. | Medium | Open |
| FR-077 | Scheduled Fetch Never Uploads | As an Operator, I want a Scheduled Fetch only to fetch and compare, and never to prepare an Upload Plan or write to the Budget App, so that every write still follows my confirmation. | High | Open |
| FR-078 | New Transaction Notification | As an Operator, I want one silent, low-priority notification, also shown as a badge on the app icon, that states the number of transactions still waiting for Upload or for my Review Decision, updated after each Scheduled Fetch and whenever that number changes and gone when it is 0, and Slussen to show no other notification, so that I know there is something to handle without being disturbed. | Medium | Open |
| FR-079 | Unattended Access Limit | As an Operator, I want a Scheduled Fetch to read the transactions of each Bank Account at most 4 times and its balance at most 4 times in any rolling 24 hours, the limit PSD2 sets (C-006), through a Data Provider that needs a Bank Consent, and to leave out a Bank Account that reached the limit with the reason and the time it ends, so that Slussen stays within the Banks' limit for access without me present. | High | Open |
| FR-080 | Fetches I Start Count as Present | As an Operator, I want every Fetch I start to be made as an access with me present, never counted against the Unattended Access limit, so that a Fetch I start is not held back by Scheduled Fetches. | Medium | Open |
| FR-081 | Change the Consent Warning Lead Time | As an Operator, I want to set how many days before its expiry a Bank Consent is flagged (7 by default) so that the warning comes as early as I need it. | Low | Open |
| FR-082 | Revoke a Bank Consent | As an Operator, I want to revoke the Bank Consent of a Bank, with Slussen asking the Data Provider to end it and deleting the stored consent and its Bank Session even when the Data Provider does not confirm, so that I can withdraw Slussen's access to that Bank at any time. | Medium | Open |
| FR-083 | Standard Import Format | As an Adopting Developer, I want Slussen to take in Transaction Files only in one Standard Import Format that it defines so that nothing in Slussen depends on a particular Bank or export format. | Medium | Open |
| FR-084 | File Pre-processor per Bank Export Format | As an Adopting Developer, I want to support a Bank's export format by writing one File Pre-processor that converts the Bank's Transaction File into the Standard Import Format so that I can import files from a Bank this build does not reach. | Medium | Open |

| FR-086 | Upload Window of a File Format | As an Operator, I want transactions from a Transaction File to be uploaded within the Upload Window that their File Format declares, which may be wider than the common one, and every transaction outside it to be shown as too old or as in the future, so that a file I import late is still uploaded and nothing disappears silently. | Medium | Rejected |
