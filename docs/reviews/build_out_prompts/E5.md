# Phase E5: the Enable Banking Fetch

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_E_enable_banking_consent.md` (§2 G9 to G12, §5 row E5, §8 R1, R2, R5). The specification: ADR-001 §4.1.1 as it now stands (the balance chosen, the mapping of a transaction's fields, paging, error codes, attendance: S-B-46, S-B-47), UC-001 (A4, A5, A9, BR-012, BR-016), Q-05 in `docs/build_out_plan.md` §6 (no Stable Reference from this Data Provider: every such Bank Transaction is Needs Review), `docs/reviews/build_out_reviews/W6-0.md`.

Read also: phases E2 to E4's code and reviews; `FetchTransactions` and the gate as phase D5 left them (`docs/reviews/build_out_reviews/D5.md`: attended and unattended requests, `bank_account_id`, the places left for Unattended Access); how `:provider-simplefin` implements a Fetch and its contract tests; O-1 and O-2 (how a Fetch's Bank Transactions and Offered Bank Accounts are stored).

Build, in `:provider-enablebanking` and `:core` (`fetch`, `request`), with `:persistence` and `:app` only where a stored column or a text needs it:
1. The plug-in's Fetch: for each Bank its session, for each Bank Account its balance and its transactions with paging (each page a request through the gate; an incomplete read gives nothing of that Bank Account), the mapping exactly as §4.1.1 states it (a missing field is never completed by guessing), each error code to its outcome.
2. The core: the sessions handed to a Fetch; A4 (a Bank without a valid Bank Consent is not contacted), A9 (a consent the Bank refuses is treated as expired from then on), A5 for each Bank (a Back-off of that Bank only); the Fetch Results per Bank Account; Provider Requests with their Bank Account.
3. Tests first against a local test server and the core's fakes: every rule of the mapping with both sides (present and missing), paging (an empty page that carries a continuation, a continuation that never ends: bounded how, a page that fails), each error, a Bank without consent not contacted, a second Bank unaffected by the first's failure; that the same history fetched twice gives the same Import Identifiers and no second Bank Transaction.

Unattended Access (A13) is phase E6: leave its counting where E6 can add it.

First, from the review of phase E2 (`docs/reviews/build_out_reviews/E2.md`):
- A Bank Account shown as an unrecognised Bank Account (its reference is not among the Offered Bank Accounts kept for its Bank) is not read by a Fetch.
