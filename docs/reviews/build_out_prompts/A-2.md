# Phase A-2: the Bank Account screen

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_A_screens_settings.md` (§1, §2 UC-008, §3 row A-2, §5 safe guesses 6 and 7, §6 risk 2).

Read also: UC-008 (all of it, step 5 especially); UC-003 (the Transaction Statuses: BR-001..BR-014, BR-018, A1, A7); UC-005 BR-002, BR-005, BR-010, A5, A8; the glossary's Transaction Statuses; UC-001 A21; `docs/transactions_plan.md` §6 (UX-01..UX-27 with the decisions UX-D1..UX-D4, O-T-11, Phase 7a's and 7b's notes); `docs/build_out_plan.md` §6; the mockup `bank-account.html` (every state; build the permanent layout, with rows and sheets read-only where their decision is not built yet) and `budget.html` for the way in; the code of Phase A-1 (the Budget tab, `ImportStatus`, `BudgetAppLine`), `slussen.core.comparison` and `slussen.core.transfer`.

Build:
1. The way from a Bank Account on the Budget tab to its own screen, and back.
2. A read model in `:core` `status` for the Bank Transactions and Unreadable Transactions of one Bank Account: newest first, with week headings, each with its Transaction Status and the reason for it in the Operator's words. The reasons, and what a status compares with (the Typed Entry a transaction matches, the Import by an Other Import Path it resembles, the other side of its Transfer), are derived with the Comparison's and the Transfer detection's own pure rules on stored data, never by a second implementation of them and never stored. O-T-11: a Bank Transaction that matches a description and has a known other side but is older than the grace period says that its other side did not arrive in time.
3. The screen: the list; the read-only detail sheets (`#tx-match…`, `#tx-possible-import…`, `#tx-unreadable…`); "What the statuses mean" (`#statuses…`); a Bank Account that was fetched and has nothing (`#fetched-empty`); the balance in another currency (`#balance-other-currency`, UC-001 A21); a currency mismatch, an unmapped and a Retired Account (`#currency-mismatch`, `#unmapped`, `#retired`) as far as they show stored data; the Funded By and Transfer Partner lines read-only; "not compared yet" for a Bank Transaction a Comparison has not reached (S-T-08). The header names the dates the list actually covers.
4. Tests: core tests for the read model, among them one that goes through every Transaction Status this build can give and asserts that the reason shown agrees with the stored status; JVM ViewModel tests for every state; a screen IT for the list, one sheet and the empty state.

Not in this phase: the Transfers screen (A-3), pull to refresh and a Fetch from the Budget tab, any decision control, the Budget switcher for many Budgets.
