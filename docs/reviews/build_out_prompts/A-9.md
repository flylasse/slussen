# Phase A-9: Export the Decision Journal (UC-011)

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_A_screens_settings.md` (§2 UC-011, §3 row A-9, §4 questions 2 and 3, §5 guess 8, §6 risk 4). The specification: the S-B-nn rows of phase W3-0 in `docs/build_out_plan.md` §6 (the export's format, what it covers, what it never contains).

Read also: UC-011 in full; NFR-012 and ADR-006 (what must never leave in clear); ADR-001 §4.2.3 (reading the Budget App) and ADR-007 §2 (an export is an operation: when it is admitted); ADR-002 §9; the mockup `journal-export.html`; phase A-8's code.

Build: the export as UC-011 states it: read as a stream, so that a large Decision Journal is never held in memory and trimming cannot corrupt it; the Budget App read fresh and not stored (the stored copy with each Budget's last read time when the Budget App cannot be read, as A2 says), so that an export never changes a Transaction Status or a cursor; the codes UC-011 asks for in place of what must not leave in clear; written to the document the Operator chooses through Android's file picker (no permission is needed), and removed again when the write fails part-way; each state of the mockup with its answer at its control. Tests first: core tests per flow and rule, among them one that proves an export changes nothing stored, and one that plants a payee, a memo and a credential and asserts none is in the file; ViewModel tests with a failing write; a screen IT as far as it can go without the system's picker.

First, from the review of phase A-8 (`docs/reviews/build_out_reviews/A-8.md`, "For phase A-9"):
- The export notes the newest entry through the Decision Journal's own thread (`RoomDecisionJournal`), so that entries queued and not written yet are inside the bound it notes.
- While the export reads, no write, trim or clearing of the Decision Journal may be blocked for the length of the read: set write-ahead logging for `journal.db` where it is opened (`SlussenDatabases.kt`) and say what that changes for the stored file and its backup rules (ADR-002 §9, §8: `journal.db` is never backed up), or read in short transactions bounded by entry ids; choose the one that needs no specification change if both work, and say which you chose.
- An export is an Operator action that the Decision Journal must not delay (UC-010 BR-004), and it must not delay a decision either: it holds no lock a decision waits for.
