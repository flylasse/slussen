# Phase D3: the HSA CSV File Pre-processor (`:fileformat-hsa-csv`)

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_D_file_import_scheduled_fetch.md` (§1 "HSA CSV format", §2 row D3, §3 questions 1 and 2, §5 R2). The specification: ADR-001 §4.3 with its part on the HSA CSV format (S-B-29 in `docs/build_out_plan.md` §6, as corrected by `docs/reviews/build_out_reviews/W5-0.md`), and "Q-01, the format" in the plan's §6. The operator's sample is not in the repository and must not be asked for: every test file is invented, in the exact layout the specification states.

Read also: ADR-001 §4.3 and §4.4 in full (the port, the Standard Import Format, what a plug-in may depend on); ADR-008 §2 and §4; NFR-007 (a rejection reason can hold file content); the module as it stands (`HsaCsvFilePreprocessor`, its profile, `FilePreprocessorContractTest` in `:plugin-api`'s test fixtures) and phase D2's code and fake.

Build:
1. `HsaCsvFilePreprocessor.convert`: the conversion exactly as the specification states it, the derived reference by the recipe exactly as written (it is permanent: reproduce the specification's test vectors byte for byte in a test, and add no normalisation the recipe does not name), every rule that rejects the whole file with a reason that names the line by its number and not its content, the lines left out as the specification says. Pure: the same bytes give the same result; no clock, no locale, no default charset.
2. The contract tests every File Pre-processor must pass, extended in the test fixtures: a rejection, references never empty, the same input twice gives the same output.
3. Tests first, with invented files: each rule of the format, each rejection, the test vectors, a file and an overlapping later export of the same invented history giving the same references for the same transactions, line endings and encodings the specification names. One test through phase D2's core with the real pre-processor: an invented file imported, then its overlapping later export, with no second Import Identifier.

Where the specification leaves a choice open, do not choose: reject the file, and list the case in your report.
