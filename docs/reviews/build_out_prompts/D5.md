# Phase D5: the Scheduled Fetch in the core, and a Fetch of one Budget (UC-001 A11, A12, A14)

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_D_file_import_scheduled_fetch.md` (§1 UC-001, §2 rows D5 and D7, §4 S8, S10, §5 R4, R5). The specification: UC-001 in full as it now stands (A11, A12, A14, BR-001, BR-005, BR-012, BR-013, BR-014), ADR-007 §1, §2, §8, and the rows S-B-38 and S-B-40 in `docs/build_out_plan.md` §6 with `docs/reviews/build_out_reviews/W5-0.md`.

Read also: the coordinator (`OperationCoordinator`: its origins, its admission, `scheduled_fetch_deferred`), `FetchTransactions` and its tests, the Request Limit and Fetch Cooldown code (attended and unattended requests), `FETCH.started_by`, and how `ImportStatus` shows a failed Fetch.

Build, in `:core`, `:persistence` (the write path only) and `:testing` (no worker, no notification: phase D6):
1. The origin Schedule in the coordinator: admitted as ADR-007 §2 says, deferred while an Upload Plan is open or an Upload is written (the stored flag), started when that ends and at a start of Slussen as the specification now says, never twice for one deferral.
2. `scheduledFetch()`: the unattended Fetch of A12 with its Comparison, its requests counted as unattended, A14 (no retry), the Request Limit Warning of A1, `started_by` Schedule, and its outcome shown afterwards from stored rows as S-B-38 says. It never prepares an Upload Plan.
3. A Fetch of one Budget (A11) as a core function, as far as the specification has it; no screen.
4. Tests first: one core test per flow and rule; the deferral and its start (not lost, not twice); a Scheduled Fetch racing an Operator's Fetch; that the existing attended path is unchanged (every existing UC-001 test passes unchanged, or you say which changed and why).

Enable Banking's Unattended Access (A13) is not in this phase; leave its counting where a later phase can add it, and say where.
