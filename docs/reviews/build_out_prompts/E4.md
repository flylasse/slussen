# Phase E4: the consent screens and the return to Slussen

Read `_common.md` in this folder first. Survey: `docs/reviews/build_out_sweep_E_enable_banking_consent.md` (§2 G3, G15, §5 row E4, §8 R4). The specification: UC-007 in full as it now stands (the return address `<application id>://consent`, pasting the address back, no device permission: S-B-43), the mockup `consent.html` (every state, the new ones of S-B-49 among them), UC-008 (the consent warning and its renew action), NFR-022, NFR-023, ADR-005 §5.

Read also: phases E2 and E3's code and reviews; `docs/reviews/build_out_reviews/A-9.md` items 5 and 6 and `D4.md` (what screens that leave the app got wrong: an unguarded launch, a control that waited, state that outlived its screen, a waiting operation that could not be left); `build-logic`'s check of the permissions (the list of NFR-022 must not change: an intent filter and a browser launch need none).

Build, in `:app`:
1. The Bank Consents part of a Data Provider's page with every state of `consent.html`: choosing the Bank (the country first, the chooser starting at the device's), granting, renewing, revoking, abandoning, each outcome with its answer at its control; the consent warning's renew action live; the lines that said Bank Consents come in a later version removed.
2. Leaving for the Bank's sign-in and coming back: the address opened in the browser (guarded: no browser answers at the control); the return through the application's own address for debug and release (formed from the application id, no Data Provider's name outside the plug-in: K-04), taken when Slussen is running, when it was stopped meanwhile, and when the answer comes twice; the pasted-back address as the fallback UC-007 describes. The answer handed to the core off the main thread; nothing of it logged or kept on screen.
3. Tests first: ViewModel tests per state and outcome; a test of the return's handling as far as plain code decides it (which intent is an answer, what is taken from it); screen ITs as far as they go without a browser (written, compiled). A list of what only a device and a real Bank can show.

First, from the review of phase E2 (`docs/reviews/build_out_reviews/E2.md`):
- The completion is called as soon as the answer arrives (its time of arrival decides whether it is late); the intent's address is never logged or kept.
- An earlier Bank Consent that could not be ended, an end the Bank did not confirm, and Offered Bank Accounts that could not be kept are each shown as they are.
- Renewing is offered only for a Bank that has a Bank Consent or whose Bank Accounts miss one.
- From the review of phase E3 (`docs/reviews/build_out_reviews/E3.md`): a start refused for its return address names the address that was sent; the credentials' form marks the return address as optional.
