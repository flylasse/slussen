# Transactions Phase 2 UX review

Reviewed 2026-10-28 against `AGENTS.md`, `docs/glossary.md`, `docs/requirements.md` (especially NFR-023), UC-001, UC-003, UC-005, UC-008, UC-010, and `transactions_plan.md` §§1 and 6. This is a source-based walkthrough of the seven requested HTML mockups, not a running-app test. A missing state means the mockups do not demonstrate the behavior; it does not establish an implementation defect. Links into excluded features were assessed as entry points only.

Journeys: **J1** upgrade, Fetch all, find this week's Bank Transactions; **J2** understand each Transaction Status; **J3** checking-to-card payment; **J4** resolve Blocked Reasons; **J5** read YNAB again and distinguish timestamps; **J6** change the fetch period to 14 days. Severity: **Blocker** prevents the journey or misrepresents money; **Major** leaves the Operator stuck or guessing; **Minor** adds friction.

The version-specific status set reviewed is New, Already In Budget App, Match For Typed Entry, Possible Import By Other Path, Needs Review (including Unreadable Transactions), Before Start Date, Too Old, In The Future, Transfer Leg and Guessed Transfer. Lonely Transfer is a Transfer condition, not an additional Transaction Status. The other glossary statuses depend on deferred Uploads or decisions; their presence in the mockups is assessed as misleading version scope, not as a request to implement those features. Already In Budget App is included because the plan expressly includes that Comparison result, without assuming that an upgrade from the balance-only version supplies Sent Records.

NFR-023 was checked on Overview, Budget, Bank Account, Transfers (status presentation and entry points), Recent Fetches, Settings, and the SimpleFIN service states. `budget.html#fetch-states` provides useful Fetch running, queued, success, failure, cooldown and blocked examples; `#budget-app-read` shows activity on the YNAB line; `#budget-app-unreadable` retains the last successful read time. The initial empty Budget names Fetch as its next action, and the currency-mismatch and unrecognised Bank Account examples name remedies. The findings below identify the remaining gaps rather than treating every static navigation link as a missing network spinner. Actual pre-request timing still needs device verification.

Review boundary: no `scratch/` or other repository was read. Consequently the Marketplace review skill referenced by `AGENTS.md`, which lives in another repository, was not read; the explicit review-only scope also precludes updating the plan's Methodology evaluation log. This limitation is recorded here for the orchestrator to carry forward. Only this report is changed.

The three findings to fix first:

1. **UX-07 — balance reported in another currency:** add A21 so a reported amount cannot be mistaken for the Bank Account's own currency or trigger the wrong repair.
2. **UX-08 — distinguish balance-reporting time from Fetch and Comparison times:** make the balance difference safe to interpret after both a Fetch and a YNAB-only read.
3. **UX-09 — complete the fetch-period journey:** correct the default and demonstrate changing it to 14 days, including in-place save and validation feedback.
