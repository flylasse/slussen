## To fix in this phase, with the orchestrator's decisions

1. **PLAUSIBLE, a gap of the specification: lines after the first empty line are dropped without a word** (`HsaCsvFilePreprocessor.kt:54-61`, as ADR-001 §4.3.1 rules 3 and 4 said). Cases: two exports pasted into one file (the second's lines are lost); one empty line among the transaction lines (every line below it is lost). **Decision:** a file whose text after the transaction lines holds the header again, or a line that gives exactly the header's fields with a first field of the form of a date, is rejected. ADR-001 §4.3.1 rule 4 and the row S-B-29 are amended (it only rejects more; no reference changes).
2. **CONFIRMED, known. A last line without a line end rejects the file** (`HsaCsvText.kt:76-77`), against rule 1 as amended in `fe6f5c6`. The last line is taken without its line end; a lone CR at the very end, and a file that ends inside a transaction line or before `Date downloaded`, still reject.
3. **CONFIRMED, minor. The contract test of a rejection's reason can pass on a leak**: it looks only for the values the implementer of a File Pre-processor lists, and an empty list passes. The list must not be empty and must hold the values of the unreadable line.

## For the question list (plan §6, G-35)

- An export whose oldest line is a reinvestment into the cash position is rejected, as the specification says: an export that begins between a dividend and its reinvestment cannot be imported as it is.
