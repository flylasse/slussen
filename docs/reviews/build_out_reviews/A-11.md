# Review of phase A-11 (6a87419..7e76f21), Start Over (UC-010 A12, FR-107)

Independent reviewer, read-only, a fresh context (Opus, as the builder: the plan's §5 row 3).

**Sound:** the interruption at each point (nothing changes before the start intent is written; from then on every start deletes from the beginning, and the intent stays until the new installation's data is committed; a file that stays stops the start before any database is opened, so no old `device.db` can stand beside a new `slussen.db`; the last good copy goes first and a new one is made only at the second start of the new installation); the intent file (not in any backup; written to a temporary file, flushed and renamed; only an exact line deletes, garbage never does); everything is deleted (the three databases with their side files, the originals set aside in both name forms and directories, the last good copy, the installation's id; a key left in the Keystore decrypts nothing; the scheduled work is cancelled before the exit and again at the new start); admission; ending the Bank Consents (each through the gate, attended, every reason named, nothing deleted before all were tried); no intent, restored state or double tap can start it; a new installation's defaults afterwards; the specification part matches the code step by step and contradicts no earlier decision.

## To fix in this phase, with the orchestrator's decisions

1. **CONFIRMED. Any launch intent can make Slussen say it started over** (`SlussenActivity.kt:105`, `ui/settings/StartOver.kt:145-149`): the result card is shown for an extra of the launch intent, which any app can send to the exported main activity, with a made-up list of Banks, on an installation whose data is all there; and the device hands the same intent in again when the task is reopened later. **Decision:** nothing of the result travels in an intent. The Banks whose Bank Consent was not confirmed as ended are written into the start intent's own file with the record of Start Over; the start that deletes reads them, and the card is shown only by a process whose start was a Start Over, until it is closed. They also survive a restart that did not happen by itself.
2. **PLAUSIBLE. The restart can fail silently, and then the app goes on showing the old data as usable** (`ProcessRestart.kt:16-17`, `ui/settings/StartOver.kt:204, 76`): a start of the activity made from a process that ends at once can be dropped, and the device blocks it when the Operator left the app while the consents were being ended; where the process stays alive the old data shows, every operation waits behind the held lane, and what the Operator enters is deleted at the next start. **Decision:** once Start Over is recorded the process always ends. From the record until its end every screen of the app shows only that Slussen is starting over; it tries to open itself again, and whether or not that works, the next opening finishes the deletion and shows the result (item 1).
3. **CONFIRMED, low. The directory is not flushed where ADR-002 says it is** (`StartSequence.kt:60-63, 168-170`), and a failed removal of the intent is ignored: a power loss right after the record can lose it (the consents ended, nothing deleted, nobody told), and an intent that stays would make a later start delete everything built since. The directory is flushed after the rename and after the removal; an intent that cannot be removed stops the start as a file that cannot be deleted does.
4. **PLAUSIBLE, low. A file that cannot be deleted ends the app at every opening without a word** (`SlussenApplication.kt:56`). The start stops, as the specification says, with a screen that says so and what the Operator can do; no crash.
5. **CONFIRMED, low. A read that fails while the consents are being ended hides which were already ended** (`core/settings/StartOver.kt:107`): the answer names them, as the answer for a record that failed does.
6. **CONFIRMED, low. The test of FR-107's last clause never runs Start Over**; it runs it. Cases for a damaged intent (a first line of garbage with the Start Over line; the first line alone).
7. **CONFIRMED, low. Texts differ from the mockup** (a part "Not contacted" of its own for missing credentials; "of YNAB and every Data Provider" is the mockup's and names a product, so the code's generic words stay and the mockup follows; "are no longer usable"; the refusal's sentence).
