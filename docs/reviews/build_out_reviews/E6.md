## To fix in this phase, with the orchestrator's decisions

1. **CONFIRMED. A Scheduled Fetch that the limit left out entirely is recorded and shown as waiting for a Back-off that does not exist** (`FetchTransactions.kt:346`): the stored outcome of a Fetch has no value for this case, and the test asserts the wrong one as right. **Decision:** the Fetch's outcome gets the value Access Limit Reached, as a Fetch Result already has (entity model, proposed as S-B-56), if that needs no schema version (a text column without a check); otherwise the builder stops and reports.
2. **CONFIRMED. The advice text says "its stored data stays unchanged"** (`Texts.kt:399-402`) in a case this phase creates: when only the transactions are at the limit, the balance is read and stored, and the balance difference beside the text rests on the newer balance. The text says which read waits for Scheduled Fetches and until when, and that a Fetch the Operator starts reads it; nothing false about stored data. A Bank Account whose balance read alone was held says so too (its Fetch Result stays Fetched, as A13 step 3 will read).
3. **PLAUSIBLE. After a balance read the gate refused for this limit, the plug-in does not read the transactions** (`EnableBankingFetch.kt:195`): reachable when the device's clock is set back during a Scheduled Fetch, since the core counts at the start and the gate at its own time; the transactions, below their own limit, are then not read and recorded as held. The plug-in goes on to the other read after a refusal of this scope, and the core and the gate count at the same time.
4. **PLAUSIBLE, at the edge. A request sent exactly 24 hours ago is not counted** (`UnattendedAccesses.kt:47`), so that a Bank counting any 24 hours closed at both ends sees one more than the limit. **Decision:** for this limit it is counted (the safe side); "free again at" follows.
5. **Tests.** A refusal by the gate driven through the plug-in; the Operator never refused through each way of starting a Fetch; "free again at" with more than the limit counted; the gate's own "one below"; the SimpleFIN test counts that Data Provider's own rows; the text test asserts what is true (item 2), not the string as written.

## Decided in the specification (S-B-56): the wording follows what W6-0 decided and this phase built

- ADR-001 §4.0: a refusal of scope Bank Account ends that read (the Bank Account's transactions, or its balance); its other read goes on; counted for each kind of read.
- UC-001 A13: the trigger names four Unattended Accesses of its transactions, or four of its balance; step 1 leaves out that read and reads the other below the limit; step 3 records Access Limit Reached when the transactions were left out; the Fetch's own outcome when everything was left out (item 1).
- The entity model: a Scheduled Fetch sends a Bank Account's unattended request of a kind only while fewer than the limit were sent in the preceding 24 hours; a Fetch the Operator started may add more (UC-001 BR-012); the Fetch's outcome Access Limit Reached.
