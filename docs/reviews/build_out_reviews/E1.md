## To fix in this phase, with the orchestrator's decisions

1. **PLAUSIBLE. After `slussen.db` is started from its last good copy, a Bank Consent can cover the wrong Bank** (`RoomStores.kt:602`, `ImportStatus.kt:446, 521`). `device.db` is kept while `slussen.db` goes back: a Bank created since the copy is missing, its key is given again to the next new Bank, and the consent and the Offered Bank Accounts of the old Bank then belong to the new one. ADR-002 §2 says that the core checks a reference from `device.db` to `slussen.db`; no check exists. **Decision:** at every start, after `slussen.db` is opened by whichever path and before anything can create a Bank, the rows of `device.db` that name a Bank `slussen.db` does not hold are removed (Bank Consents with their Bank Sessions, Offered Bank Accounts), all or nothing; the Bank's Bank Accounts then show a missing consent, which is true.
2. **CONFIRMED. A refused consent is not shown as UC-008 BR-006 and UC-001 A9 step 3 say** (`SettingsOverview.kt:390-395` reads only the expiry; in `ImportStatus` a refusal cannot be told from an ordinary expiry). Not reachable until a later phase marks a refusal; fixed here so that the phase that does finds it right: the status carries that the Bank refused it and when, and the Settings overview treats the consent as expired from then.
3. **CONFIRMED. Revoke deletes fewer Consent Requests than specified** (`ConsentTables.kt:230` and the fake): UC-007 BR-007 and ADR-002 O-10 say every Consent Request of the Bank; the code deletes those of the same Data Provider only, so an unanswered request of another Data Provider for that Bank survives. The code follows the specification.

## For phase E2 (in its prompt)

- The Bank's row (`slussen.db`) and the Bank Consent (`device.db`) are written to two databases: within one operation on the lane, consume the answer, complete at the Data Provider, find or create the Bank's row, then store the consent once. When the completion is refused, when something throws, and at a start after a process that ended in between: a Bank's row that this attempt created and that nothing refers to is removed.
- The Bank's reference is at most the length the entity model gives it: enforced in the core.

## For the end checklist

- A build that carries `device.db` version 2 must have a higher version code than the one installed: an older build meeting a version 2 file cannot open it (no data is lost; Android refuses a lower version code but accepts an equal one).
- On the JVM the DAO's query strings are not run (the store's test replaces them by lists); `UC007GrantBankConsentPersistenceIT` and `DeviceDatabaseMigrationIT` are their check, on the phone.
